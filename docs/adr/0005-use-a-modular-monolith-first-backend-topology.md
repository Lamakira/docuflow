# Use a modular-monolith-first backend topology

DocuFlow will evolve its current backend into a modular monolith in one repository, with one authoritative PostgreSQL database and separate HTTP and durable-worker runtimes built from the same codebase. Domain modules own their implementation and persistence behind explicit interfaces; immediate invariants use synchronous calls, deferred consequences use transactional-outbox events, and legacy contracts survive temporarily through thin adapters. Distributed services were rejected as the starting topology because Workspace and domain seams are not yet stable enough to justify distributed consistency and operational costs; a module may be extracted only after its interface and data ownership stabilize and a measured scaling, isolation, runtime, or reliability need outweighs those costs.
