# Use Workspace-scoped shared-schema tenancy

DocuFlow will use pooled PostgreSQL tables in a shared schema, with an immutable `workspace_id` stored on every Workspace-owned row and propagated through every request, worker, cache, queue, object, search record, analytics event, and audit record. Application scoping, composite relational constraints, and PostgreSQL row-level security enforce isolation in depth; only a small allowlist of identity and system control data is global, while privileged cross-Workspace operations use a separate audited interface. Schema-per-Workspace and database-per-Workspace were rejected for the initial architecture because their migration and operational cost is not justified; a Workspace placement seam and single home-region assignment preserve a path to later database or regional relocation.
