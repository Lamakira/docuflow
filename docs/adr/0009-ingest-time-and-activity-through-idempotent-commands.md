# Ingest time and activity through idempotent commands against server-authoritative state

DocuFlow's Time module owns a server-authoritative Timer state machine — at most one active Timer per User, enforced by a partial unique index — and every surface, web and desktop alike, submits idempotent Timer Commands carrying origin, per-origin sequence, claimed effective time, and explicit Workspace scope. Commands apply in effective-time order and materialize Time Entries that split on pause and on overlap; late arrivals trigger bounded re-materialization while the append-only command log serves as provenance. Claimed device times pair with server receive times under monotonic-clock anchoring, are clamped to the present, and are flagged rather than rejected. Activity Evidence enters through two-phase uploads and thin idempotent batch commits whose derived processing and attribution ride outbox workers; capture obeys immutable versioned Tracking Policy with a cache TTL that fails capture closed and the Timer open, and stale-cache captures violating capture-time policy are purged, never stored. An event-sourced command log as the source of truth, device-authoritative reconciliation, and rejection of offline work were all rejected: DocuFlow wants determinism exactly where overlaps resolve, without replay machinery, and no Member time lost to synchronization.
