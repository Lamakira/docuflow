# Serve retrieval and AI through an Intelligence module

DocuFlow adds a tenth domain module, Intelligence (amending ADR-0008's nine-module count), owning index artifacts, ingestion pipelines, knowledge retrieval, the AI provider gateway and adapters, the AI Purpose taxonomy, Workspace AI Policy, and content-minimized AI audit — policy staying with its enforcement engine. Retrieval covers the knowledge corpus only (Documents, File extracted text, Transcripts); operational lookup remains per-module composed queries. The first-wave engine is PostgreSQL full-text search plus pgvector in the authoritative database, outbox-fed, with index rows carrying full provenance (workspace, source type/id/revision, chunker and model versions, dimensions, policy version, generation); model or chunker migrations run as side-by-side index generations with per-workspace atomic cutover, and extraction to a managed search service happens only on measured relevance or latency thresholds behind the seam. Index rows duplicate no ACLs: retrieval joins canonical Document Access and Project Assignment at query time, so access changes need zero index propagation, while deletions ride the ADR-0012 purge cascade with a nightly reconciliation sweep and citations re-check access at read time. A thin DocuFlow-owned gateway exposes `generate`, `embed`, and `transcribe`; before any external call it authorizes capability and Document Access, evaluates Workspace AI Policy and purpose, minimizes payloads, allowlists provider/region/retention mode, and enforces budgets, rate limits, and circuit breakers, leaving a content-minimized audit event per call. Initial providers are direct OpenAI for embeddings and generation — EU regional processing pursued as a tracked gate, hyperscaler model plane the named successor if hosting lands on a cloud — and provisionally Azure Speech for first-party speech-to-text (French and English launch languages), final selection gated on a consented benchmark. Transcripts are immutable Knowledge content attached to a File Version or import, copy-out only; Loom browser-scraping is retired outright, importers exist only where official APIs do, and legacy `video_transcripts` rows migrate as `legacy-import` Transcripts while legacy embedding tables are dropped and rebuilt. AI Answers persist per user and workspace with citations and configurable retention; AI is on by default under a non-negotiable floor (no-training providers, payload minimization, no raw prompt logging) with per-purpose opt-out; capabilities are entitlement-gated and metered per workspace and purpose in units; lexical search is the guaranteed no-external-call floor, semantic features fail explicit rather than silently empty, transcription queues through outages, and generation hard-stops at budget exhaustion. V1 performs no automatic PII redaction — no-training terms, retention modes, and purpose limitation carry privacy, with provider redaction add-ons reserved as a policy option. A managed search service now, LiteLLM or a hyperscaler plane as the gateway, denormalized index ACLs, editable transcript documents, quarantined scraping, unified operational search, day-one PII redaction, and unmetered AI were all rejected.
