# Migrate to the target architecture in place through nine gated phases

DocuFlow reaches the target architecture by evolving the production backend in place — no parallel rebuild — through nine dependency-ordered, overlapping phases, each made of small expand/contract deploys with its own verifier, temporary feature flag, and rollback path: (1) stabilize — remove Replit sidecar and connector dependencies, containerize, add CI/CD with synthetic staging, consolidate every schema change into Drizzle-generated plain-SQL migrations applied as a gated pre-deploy step, delete boot-time DDL and data mutation, capture characterization and contract tests on the legacy web API and desktop v1 protocol, establish the OpenTelemetry baseline, and replace the ephemeral desktop JWT secret with a persistent versioned signing key; (2) lift hosting onto Render, Neon Frankfurt, and the AWS evidence account while GCS keeps serving objects; (3) stand up the worker runtime, jobs port, and outbox so process-local intervals and unawaited promises become durable jobs before any replicas or backfills; (4) establish the Workspace seam — seed one Workspace and Memberships (`isMainAdmin` → Owner, `admin` → Administrator, `user` → Member, special flags → explicit capabilities, archived users → Archived Memberships, `org_settings` → Workspace policy rows), backfill workspace lineage per table through nullable column → resumable backfill job from aggregate roots outward → zero-orphan verifier → `NOT NULL`, add core composite uniques, enable RLS table-by-table only after query scoping is verified, and drop Teams after snapshotting them into migration evidence; (5) migrate identity to Clerk by bcrypt-hash import with a dual-auth drain window and password-set invites for any OIDC-only accounts, then remove Replit OIDC and `MCP_API_KEY`, leaving enrolled desktop devices untouched; (6) carve modules out of `routes.ts`/`storage.ts` incrementally, carrying the Opportunity/Project stage-rule split (legacy IDs stay on the Project; `documented` rows get no Opportunity), the Document/File split (existing object keys preserved, access defaulting to everyone-in-workspace, embeddings dropped and rebuilt), the GCS → R2 bulk-copy, dual-write, read-flip move, and legacy Time Entries kept with `legacy` provenance and no synthesized Timer Commands; (7) expose the new contract surfaces; (8) take billing live with the legacy workspace on a pinned plan; (9) retire legacy surfaces.

While production serves only the internal single tenant, bounded announced maintenance windows are allowed for the hosting and identity cutovers; everything else ships zero-downtime. Cross-cutting rules: DocuFlow-owned DB-backed feature flags behind a small cached port, each migration flag temporary with a named owner and removal gate; verification through pre-captured contract tests run continuously against adapters, a verifier per backfill, shadow-read comparison reserved for authorization and storage-port swaps, and post-cutover reconciliation counts; rollback by image redeploy and flag-off with old columns and paths retained until contract drops; every destructive drop gated on zero-reference telemetry for 14 days plus two backup cycles; desktop v1 endpoints removed once the force-updated internal fleet shows two weeks of zero v1 traffic, with ADR-0011's deprecation windows applying only to the new protocol once external customers exist; the legacy web API retiring only after v2 UI cutover so backend and UI never block each other; and per-phase evidence — verifier outputs, seed and classification snapshots, cutover timestamps — recorded in `docs/migration/` as the compliance-grade migration trail. A build-then-cutover rewrite, zero-downtime-everywhere discipline, a third-party feature-flag service, converting Teams into Project Assignments, and synthesizing Timer Commands for historical entries were all rejected.
