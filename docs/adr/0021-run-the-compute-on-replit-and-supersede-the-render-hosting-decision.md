# Run the compute on Replit and supersede the Render hosting decision

Supersedes ADR-0016 on the compute plane only. DocuFlow's two runtimes stay on Replit rather than moving to Render, because Replit is already paid for, already carries the production database and a managed Clerk tenant, and — since Phase 1 removed the sidecar and connector coupling recorded in ADR-0017 — the application now reads every credential from its own environment, which turns Replit from a platform the product depends on into one host among several. Everything else in ADR-0016 stands unchanged: Cloudflare R2 with the `eu` jurisdiction behind the storage port, the standalone Object-Locked AWS account for evidence, OpenTelemetry into Better Stack and Sentry, Cloudflare in front, the €300–500/month ceiling with 80%-of-budget alerts, the 99.9% HTTP SLO, and the worker-lag SLO of 95% of jobs started under 60 seconds. Removing the Render line item is the point of the change; it bought capability the organization was already paying Replit for.

Four platform mechanics shape how the phases execute. **Geography** is chosen at first publish and is permanent — it cannot be changed afterwards — so the parallel environment publishes to the Europe (EU) geography, which colocates compute, database, and Object Storage; the plan must be Core or above, since Free publishes to North America by default, and the specific EU city is not documented, so this repository claims EU residency and not Frankfurt. **Development environments run in North America regardless of publishing geography**, which makes ADR-0018's snapshot rehearsal a data-residency question rather than only an isolation question: restored production snapshots must never be loaded into a Replit development database, and every rehearsal runs against a database placed in the published EU environment. **The worker runtime requires a Reserved VM deployment**, which never sleeps; Autoscale is request-driven and scales to zero, so it cannot host ADR-0013's lease-elected in-app scheduler, and the current `deploymentTarget = "autoscale"` in `.replit` covers only the HTTP runtime. **Migrations run as the deployment Build command**, whose failure fails the build and blocks the publish — that is the gated pre-deploy step ADR-0017 requires and the mechanism by which reassigned gate G4 can be proved. Because Replit documents no Docker or custom-container deployment path, the Dockerfile shipped in Phase 1 stops being the deployment artifact and remains what it also always was: the CI harness and the portability insurance that keeps this decision reversible.

Three consequences are accepted with their costs named, and three questions gate execution rather than being answered here. Accepted: the production database is Neon while the development database now runs on Replit's own Helium Postgres, so the two environments are the same PostgreSQL 16 dialect but not the same operator, and the migration journal — not Agent-applied schema changes propagated at publish — stays the single authority over schema in both, with the Agent's schema path kept off; published-version rollback no longer works the way ADR-0016 assumed, since a published app is reverted by rolling the project to an earlier checkpoint and publishing again rather than by redeploying a prior image, which makes expand/contract discipline and the never-a-down-migration rule load-bearing rather than merely prudent; and ADR-0018's isolation now means two separate Replit projects with disjoint secrets, because the very argument that motivates this decision — the subscription is already paid — is also the pressure that would put migration work in the same project as production. Gated: **point-in-time restore is not documented for the Replit production database** — only a seven-day soft-delete window for deleted databases — so ADR-0016's RPO of five minutes is unevidenced on this platform, and until it is confirmed the real recovery point is set by our own nightly logical exports to the AWS evidence account, which the exposed `DATABASE_URL` does permit; **whether one project can run an HTTP deployment and a Reserved VM worker deployment simultaneously is undocumented**, and if it cannot, the worker needs its own Replit project against the same repository; and **the Replit-managed Clerk tenant is not exposed through the Clerk dashboard**, being administered from Replit's Auth tool instead, with no documented export path for its users — so Phase 5 adopts that managed tenant only once an export path is confirmed, and otherwise uses a DocuFlow-owned Clerk account, because a tenant we cannot export from converts ADR-0007's replaceable identity seam into a dependency whose exit cost is unknown.

Render was rejected as a second bill for capability already purchased. Autoscale for the worker was rejected because a scheduler that sleeps is not a scheduler. Letting the Agent own production schema was rejected because it reintroduces exactly the boot-time and out-of-band DDL that Phase 1 deleted. Treating the Dockerfile as the deployment artifact was rejected as unsupported on this platform, though it is retained for CI and portability. Publishing to the North America geography was rejected because the data-plane residency decision in ADR-0016 is not a preference. Reversing Phase 1's de-Replit work was never at stake: that work removed connector coupling, not hosting, and it is what makes this decision cheap to undo.
