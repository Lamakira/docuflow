# Prefer Replit-provided capability wherever an exit can be proved

Where Replit provides a capability DocuFlow needs, DocuFlow uses it rather than buying a second tool for the same job. The subscription is already paid at the Pro tier, the marginal cost of capability inside it is near zero, and every additional provider is another account to create, another credential to hold, another bill to watch, another spend alert to wire, and another vendor relationship for a small team to carry. ADR-0021 removed the Render line item on exactly this reasoning and this decision generalises it: consolidation is the default, and a second tool needs a reason rather than an absence of one. The test that keeps this safe is not who provides the capability but whether DocuFlow can get its data back out — a capability is adopted only when an exit can be demonstrated, and the demonstration is a documented path or a path we can build and run, not an expectation. This is not a new constraint: ADR-0016 already requires "plain-SQL migrations and no Neon-only features so the database and compute vendors stay independently replaceable", and ADR-0021's entire case for staying on Replit is that Phase 1's work leaves the arrangement "cheap to undo". This decision names that property, applies it uniformly, and makes failing it the only grounds for refusing a Replit-provided tool.

Four planes are scored against the test and three pass. **Compute** passes because Phase 1 removed the sidecar and connector coupling, the application reads every credential from its own environment, and the Dockerfile is retained as CI harness and portability insurance. **The databases** pass because production Neon and development Helium are the same PostgreSQL 16 dialect reached through an exposed `DATABASE_URL`, the migration journal is plain SQL with no vendor-only features, and the nightly logical exports to the standalone AWS evidence account are an independent copy by construction. **Object storage** passes conditionally, and the condition is recorded rather than waved through: Replit App Storage is backed by Google Cloud Storage and reachable through the standard `@google-cloud/storage` client library as well as Replit's own SDK, and that SDK exposes per-object list, download, upload, copy, and delete — so an exit exists as list-then-download, a script DocuFlow writes and owns, with a cost that is knowable even though no vendor bulk-export is documented. **Identity fails**, and it is the sole exception: the Replit-managed Clerk tenant is administered from Replit's Auth tool rather than the Clerk dashboard, no export path for its users is documented at any level, and unlike the object plane there is no underlying standard client to fall back to. DocuFlow therefore provisions and owns its own Clerk account, as ADR-0021 already provided for, and identity is the one place this decision buys a second bill deliberately.

Three consequences are accepted with their costs named. **The parallel environment's object storage becomes Replit App Storage**, which supersedes the Cloudflare R2 line ADR-0016 set and ADR-0022 scheduled: R2 leaves the parallel environment, no separate object-storage account or bill is created, and the residency requirement is met by the publishing geography rather than by a jurisdiction setting, since ADR-0021 records that publishing to a geography colocates compute, database, and Object Storage. ADR-0022's substance survives the provider change unaltered — the operator-run, key-preserving snapshot copy ordered at or after its paired database export, the scrub of absolute storage URLs out of the restored database, the copy manifest as Phase 2 evidence, and the dangling-key verifier — because none of it depended on which vendor held the bucket, and the `desktop_releases.storage_url` hazard it identified becomes *more* acute rather than less, since a GCS-backed destination shares the `storage.googleapis.com` host that `downloadRoutes.ts` validates, so an unscrubbed production row now passes a host check that would previously have caught it. **Phase 1's gate G1 is knowingly regressed in scope.** G1 removed Replit sidecar and connector dependencies and the Phase 1 record marks it Verified at its evaluated revision, which remains true of that revision; adopting App Storage reintroduces a Replit-provided storage dependency, and the honest statement is that the coupling is materially weaker than what G1 deleted — a standard client library against a bucket, not a sidecar injecting credentials — but it is a dependency and it is recorded as one rather than absorbed silently. **One question is left open and named**: whether the standard GCS client can reach an App Storage bucket with a credential DocuFlow holds, or only through Replit-injected authentication. If only the latter, the exit path runs on the platform being exited, which weakens but does not void it, and the answer belongs to the ticket that wires the bucket.

Amended since: the open question above is answered, and against this decision's expectation. Probed in the provisioned App on 2026-08-13, **the standard `@google-cloud/storage` client cannot reach an App Storage bucket at all** — no Google credential is injected, and access runs through `REPL_IDENTITY` against the connectors host, which means `@replit/object-storage` and nothing else. Three consequences follow and each is worse than what this decision assumed. The scoring above called object storage's coupling "a standard client library against a bucket, not a sidecar", and that sentence is now false: **Phase 1's gate G1 is undone on the storage plane rather than regressed in scope**, because the connectors sidecar is precisely what G1 deleted. The exit this decision conditioned adoption on **runs on the platform being exited** — list-then-download through the platform's own SDK — which weakens it without voiding it: the path exists, DocuFlow owns the script, and the cost is knowable, but it is unavailable the moment the platform is. And ADR-0016's direct signed transfers **do not hold here**, since the SDK cannot sign: every object byte moves through the server, which the object-storage cost model puts at roughly 2.1 TB/month at the month-12 envelope, on a host that bills per request and per unit of compute. Two smaller items are recorded rather than settled: ACL policy lives in a sibling `.acl.json` object beside each object, a stopgap the code names as one, since ADR-0012 makes the database row the policy's proper home; and `list` is now part of the storage port ([#59](https://github.com/Lamakira/docuflow/issues/59)) precisely because this decision's exit test is unwritable without it — a capability no request path uses, kept because the argument for adopting this provider depends on it. Detail in [PR #72](https://github.com/Lamakira/docuflow/pull/72) and `docs/migration/phase-2-object-snapshot.md`. None of this reverses the decision: the alternative remains a second provider, a second credential, and a second bill, and the exit is demonstrable where it was previously only expected — but it is adopted now with its real coupling on the record rather than a softer one.

Buying a second object-storage provider was rejected as the second bill this decision exists to avoid, now that an exit from App Storage has been shown. Adopting the Replit-managed Clerk tenant for consistency was rejected because consistency is not the principle — exit-ability is — and identity is both the plane that gates every request and the only one ADR-0018's export-import-verify rehearsal could never exercise. Applying the preference without the exit test was rejected as the version of this decision that would be regretted rather than reversed, since a preference with no failure condition is not a decision but a habit. Keeping R2 solely to preserve ADR-0016's wording was rejected because ADR-0016's storage line served the residency and cost goals that App Storage also serves, and the wording is not the goal. Treating the already-paid subscription as a reason to adopt a capability we could not leave was rejected outright: that is the argument ADR-0021 identified as the pressure to guard against, not a justification.
